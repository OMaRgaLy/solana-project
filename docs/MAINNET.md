# Выход на Solana Mainnet

## Как устроено

У сайта две сети, и выбираются они прямо в браузере:

| | Основная сеть (mainnet) | Демо режим (devnet) |
|---|---|---|
| Деньги | реальные SOL | тестовые, ничего не стоят |
| Кошельки | только настоящие (Phantom и т.п.) | встроенные демо-кошельки и Phantom |
| Как попасть | сайт стартует здесь | кнопка «Демо режим» в шапке |
| Бот | `/wallet`, `/my`, `/tax`, уведомления | `/demo` (всегда devnet) |

Демо-кошельки подписывают только в devnet: на mainnet они недоступны ни на сайте, ни в боте, потому что их ключи публичные.
Ссылка на счёт работает у любого посетителя: сайт сам находит, в какой сети лежит счёт, и переключается в нужный режим.

**Пока контракт в mainnet не опубликован, сайт стартует в демо (devnet)** и кнопки «Демо режим» нет: переключаться некуда.
Как только вы зададите `NEXT_PUBLIC_PROGRAM_ID_MAINNET`, сайт начнёт стартовать в mainnet, а «Демо режим» станет кнопкой.

## Три понятия простыми словами

- **Программа (контракт)** — наш код, который делит платёж. Он «установлен» в сети и живёт по своему адресу, как номер счёта.
  Сейчас он установлен только в тестовой сети, а в основной его ещё нет: у mainnet отдельная копия и отдельный адрес.
- **Ключ программы** — файл, из которого получается адрес программы. Для mainnet нужен новый, не тот, что на devnet. Никому не показывать и не коммитить.
  Отдельно есть ключ обновления: кто им владеет, тот может менять программу. Его надо хранить как деньги.
- **RPC** — сервер-посредник, через который сайт разговаривает с блокчейном. Публичный адрес бесплатный, но ограничивает число запросов,
  и под нагрузкой сайт начнёт «подвисать». Платные провайдеры (Helius, QuickNode, Alchemy) дают личный адрес с ключом, у многих есть бесплатный тариф.

## Шаги

1. **Новый ключ программы** (не используйте ключ с devnet):
   ```
   solana-keygen new -o ~/steppe-mainnet-program.json
   solana-keygen pubkey ~/steppe-mainnet-program.json
   ```
   Подставьте адрес в `declare_id!` в `programs/steppe_invoice/src/lib.rs` и в `Anchor.toml`, затем `anchor build` (в Windows через WSL).

2. **Стоимость публикации.** По умолчанию программа резервирует место вдвое больше своего размера (на обновления).
   ```
   ls -l target/deploy/steppe_invoice.so              # размер в байтах, N
   solana rent <2*N + 45>                             # залог за аккаунт программы
   ```
   Залог возвращается только при закрытии программы. Дешевле: `--max-len N`, но тогда большую версию без переустановки не выложить.
   На кошельке для публикации должно быть столько SOL плюс запас на комиссии.

3. **Публикация.**
   ```
   solana config set --url mainnet-beta
   solana program deploy target/deploy/steppe_invoice.so --program-id ~/steppe-mainnet-program.json
   ```
   Ключом, которым публиковали, управляются обновления. Позже передайте его мультиподписи (например, Squads) или закройте обновления.

4. **Кошелёк платформы (комиссия 1%).** Уже задан в коде: `FtRMty97BNBxvEMWAw2Xv9AaNCrD83CyKiNdcyhVKQpG`
   (`DEFAULT_TREASURY` в `app/lib/cluster.ts`). Другой адрес можно указать в `NEXT_PUBLIC_TREASURY`.

5. **Переменные на хостинге** (Vercel → Settings → Environment Variables), затем Redeploy:
   ```
   NEXT_PUBLIC_PROGRAM_ID_MAINNET=<адрес программы из шага 1>
   NEXT_PUBLIC_RPC_URL_MAINNET=<ваш RPC для mainnet>
   ```
   Переменные `NEXT_PUBLIC_PROGRAM_ID` и `NEXT_PUBLIC_RPC_URL` остаются для devnet (демо режим).

## Что нужно знать до реальных денег

- **Комиссия не принудительна на уровне контракта.** Получателя комиссии указывает создатель счёта при создании, контракт этого не проверяет.
  Через сайт и бота 1% идёт на кошелёк платформы, но технически подкованный пользователь может вызвать контракт напрямую и указать себя.
  Чтобы 1% был гарантирован, нужно изменить контракт (зашить адрес платформы и минимальную долю) и протестировать до публикации в mainnet.
- **Контракт не прошёл независимый аудит.** Хотите ограничить риск — ограничьте максимальную сумму счёта и скажите об этом открыто.
- **Только SOL.** Курс колеблется между счётом и оплатой. USDC — следующий шаг.
- **Девнет-работа не доказывает mainnet.** Логика та же, но в основной сети ошибка стоит реальных денег и необратима. Минимальная проверка после публикации:
  один счёт на копейки, оплаченный вторым кошельком, с проверкой в Solscan, что 1% дошёл на кошелёк платформы.
- **Юридически.** Сбор комиссии с платежей в крипте может требовать лицензии или регистрации. Это вопрос к юристу.
- **Blink в X** разворачивается только на домене, зарегистрированном в Dialect.

## Откат

Уберите `NEXT_PUBLIC_PROGRAM_ID_MAINNET` и сделайте Redeploy: сайт снова стартует в демо режиме.
